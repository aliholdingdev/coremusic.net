# K011-application/event-akislari — Web Araştırması

**Amaç:** Bu belge `event-akislari` klasörü için spec §9 havuzundaki 5 MDN URL'sini
`webfetch` ile erişir, `curl.exe -L -s -o NUL -w "%{http_code}"` ile HTTP 200 doğrular,
her URL'den çıkan claim'i repo kanıtıyla eşler (claim↔repo matrisi), reddedilen adayları
yalnızca etiketler ve kesişim kontrolünü PowerShell bloğu olarak metin verir. Havuz dışı
URL eklenmez.

### §1.1 Erişim notları (webfetch çıktısı)

| # | URL | webfetch durumu | Dikkat çeken claim |
|---|-----|-----------------|---------------------|
| 1 | EventTarget | ✅ metin alındı | "any target of events implements the methods associated with this interface" · `EventTarget()` constructor · `when()` Observable (yeni) |
| 2 | addEventListener | ✅ metin alındı | "If the function or object is already in the list of event listeners for this target, the function or object is not added a second time" · options: `capture/once/passive/signal` · "Repeatedly defining the same unnamed function … can be problematic" · `removeEventListener` için static referans şart |
| 3 | dispatchEvent | ✅ metin alındı | "invokes all applicable event handlers synchronously before returning" · `isTrusted` false (synthetic) · "exceptions do not propagate to the caller" (handler istisnası yayıcıyı düşürmez — warning bloğu) |

| 5 | EventListener | ✅ metin alındı (redirect) | Sayfa `EventTarget/addEventListener`'a yönlendirildi; claim'ler oradan alındı (§2.5) |

## §7 — MDN claim ↔ iki JS mekanizması çapraz matrisi (dogrulama §7.1 ile uyumlu)

Repo'da **iki ayrı** olay mekanizması vardır: (A) `EventBus` pub/sub (`js/core/EventBus.js`),
(B) `ComponentBase` DOM `CustomEvent` (`ComponentBase.js:209-212` `dispatchEvent(new CustomEvent('cm:…'))`).
MDN claim'lerinin hangi mekanizmaya ait olduğu aşağıdadır — bir claim'in "A'da yok" olması
