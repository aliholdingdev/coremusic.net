# Session: Fix Login Bug + Gender-Based Login Restriction

## Goal
1. Fix first-login failure (session race condition on Windows)
2. Implement gender-based login/registration restriction

## Status: COMPLETED

---

## Changes Made (5 files)

### 1. `shared/src/PageRouter\ResponseEmitter.php`
**Fix: Session persistence before exit (Issue 1 root cause)**

Added `session_write_close()` before `exit` in:
- `sendJson()` (line 48-50)
- `sendHtml()` (line 74-76)
- `redirect()` (line 85-87)

**Why:** On Windows with file-based sessions at `C:\temp`, PHP writes session data at script shutdown. When `exit` is called, the session file may not be fully written before the next AJAX request reads it. Explicit `session_write_close()` ensures the session is persisted to disk before the response is sent, eliminating the race condition where the first login attempt fails.

## How It Works

### Gender Flow:
1. User visits `auth.coremusic.net` → redirected to `/select-gender`
2. User picks gender → `POST /set-gender` → `SessionManager::setGender()` stores in `$_SESSION['cm_gender']` + cookie `cm_gender`
3. User goes to `/login` → gender is in session
4. User submits login → `AuthController::handleLogin()` passes `$this->session->getGender()` to `AuthService::login()`
5. `login()` checks: if visitor gender is `male`/`female`, only accounts with matching DB gender can login
6. Same for `register()` — registration gender must match visitor's selected gender

### Error Messages (Turkish):
- Login: "Bu cinsiyet seçimiyle bu hesaba giriş yapamazsınız. Sadece erkek hesaplar erişebilir."
- Register: Same message

### Neutral Fallback:
- If visitor selects "neutral" (nötr), ALL accounts can login/register — no restriction
- This is the default behavior when `$visitorGender = 'neutral'`
